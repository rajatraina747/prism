# Prism 2.3.0: third-party review, 2026-09-28

Scope: the whole tree at `main` 50ff3c8 (v2.3.0), about 45k lines of Rust, TypeScript and CI.
This review was done **from the code alone**: README, `docs/`, ROADMAP, release notes and every
earlier review were deliberately not read, and code comments were treated as claims to check.
Four passes: Rust backend security; engines and queue correctness and performance; front-end code,
performance and UI/UX; configuration, CI and dependencies. Every Critical and High finding was
re-read at the cited lines by the reviewer.

Evidence at review time: `tsc` clean (app + node projects); `eslint` clean; vitest **397/397**;
Rust `cargo test --lib` **273 passed, 4 ignored, 0 failed**; Playwright 26 specs (not re-run).

---

## 1. Verdict

Prism's **perimeter is strong**, stronger than most commercial downloaders:
- **Commands:** every IPC command is granted by name to one window, with a build-time manifest and tests.
- **Arguments:** every URL goes after `--`, and yt-dlp runs with `--ignore-config --no-plugin-dirs`.
- **Player:** mpv runs with `config=no`, `load-scripts=no` and `access-references=no`.
- **Stream server:** loopback only, a 32-byte token compared in constant time, and an exact `Host` check.
- **Storage and updates:** SQL is fully parameterised; the updater checks minisign signatures; zip-slip is guarded.
- **CI:** actions are pinned to commit SHAs, and the signing key sits in a protected environment.

The weaknesses are elsewhere, in three themes:

1. **Cleanup paths trust the page and delete by name.** Cancel, fail and retry are the least-tested
   code in the tree. The worst finding (D-1) lets an ordinary Cancel permanently delete an
   unrelated file, and lets a compromised webview delete files anywhere under home, while every
   other path check in the backend is bypassed.
2. **Two queue engines.** Rust owns the queue now, but a ~700-line frontend engine
   (reducer, slots, retry, schedule, completion) survives for the web demo and still makes
   decisions in desktop mode. They have already drifted.
3. **Linear-cost hot paths.** Performance is fine at typical scale, but several paths cost more
   as the queue grows: whole-table SQLite rewrites every 2 s, whole-item patches (torrent file
   lists included) every second, and every queue row re-rendering on every progress tick.

| Area | Grade | One-line reason |
|---|---|---|
| Security | **B+** | Excellent perimeter; one High in the cancel path, a memory-safety bug in vendored FFI, Windows UNC gaps |
| Correctness | **B−** | Race-safe queue rules; cleanup, retry and failure paths leak or over-delete |
| Performance | **B** | Nothing slow at 50 items; several O(queue) costs per tick at 500+ |
| Code quality | **B** | Well-commented, well-tested pure modules; four oversized components, a duplicate engine |
| UI/UX | **B−** | Feature-rich and mostly consistent; terminology drift, a dead-end status, keyboard hijack, a cramped Settings |
| Test/CI | **A−** | 279 Rust / 397 TS / 26 e2e, audits in CI; Rust tests never run on macOS |

## 2. Critical and High findings (all confirmed at source)

### D-1: Cancel permanently deletes files it didn't write (data loss, security)
`src-tauri/src/queue.rs:394-438` (`video_template`, `discard_engine`), `queue.rs:858-879`
(`queue_add`), `download_manager.rs:943-990` (`discard_stopped`, `run_files`, `companion_files`).

When a paused yt-dlp item is cancelled, Rust:
- rebuilds its output template **from the item JSON** (`settings.destination`, only tilde-expanded);
- takes the cut-off time from `metadata.source.addedAt`, falling back to `UNIX_EPOCH`;
- `remove_file`s (not Trash) every file in that folder whose name starts with `"<name>."` and is
  newer than the cut-off, whenever no finished media file shares the name.

It never goes through `validate_download_path`, the ledger or the Trash keep-list.
- **In ordinary use:** cancelling a paused "Episode 1" deletes a finished "Episode 1.5 Special.mp4"
  written since Episode 1 was added.
- **As an attack:** `queue_add` accepts any JSON object with an id. Script in the main window can
  plant `{status:"paused", settings:{destination:"~/Documents", filename:"thesis"},
  metadata:{source:{addedAt:"1970-01-01T00:00:00Z"}}}` and call `queue_cancel`, which deletes
  `~/Documents/thesis.*`. The torrent branch (`discard_stopped_magnet`) similarly removes empty
  trees under a page-chosen path.

Related (C-3): the rebuilt name ignores the `(1)` de-duplication the run actually used, so
cancelling a paused duplicate can delete its sibling's live `.part`.

**Fix:** at start, Rust records the exact output claim per id (extend `DownloadManager.reserved`
and persist it with the item, Rust-side). Cancel then deletes only that claim's files: exact
yt-dlp suffixes (`.part`, `.fNNN.ext.part`, `.part-FragN`, `.ytdl`, `.LANG.srt/vtt`, thumbnail),
moved to the Trash via the `trash` crate already in the tree. `queue_add` validates or strips
`settings.destination` with `validate_download_path`. Revoke `store_save_queue` (unused in
desktop mode, a second way to plant items).

### D-2: A stale retry timer knocks a live download back to "queued"
`queue.rs:643-657`, `queue_rules.rs:180` (`requeue_for_retry`).
The backoff timer carries no generation token, and `requeue_for_retry` only checks
`status == "downloading"`. If the user pauses and resumes, or presses Retry, inside the backoff
(60 s for rate limits), the old timer fires on the *new* run. The item goes to `queued`, its
progress and success are then ignored, and the next tick starts a second copy as `Title (1)`.
**Fix:** a per-id generation counter bumped by pause, resume, retry and cancel, or requeue only
if `retryAt` still matches.

### D-3: Failed torrents stay alive in the librqbit session
`torrent.rs:964-967`, `990-994`, `1022-1033`; `emit_failure` at `torrent.rs:1912`.
On an engine error, the "give up after N minutes" limit or a failed re-check, the torrent is
removed from Prism's `active` map and reported failed, but `session.delete` is never called. It
keeps announcing, and downloads if peers appear, with no UI row. `cancel_torrent` can't find it.
It persists until the next launch prunes it.
**Fix:** `session.delete(handle.id(), false)` before each `emit_failure` in the poll loop.

### D-4: Use-after-free in the vendored libmpv event callback
`vendor/tauri-plugin-libmpv/src/desktop.rs:38-67` vs `196-204`.
`event_callback` dereferences the userdata box and moves *references* (`app`, `window_label`)
into a spawned task. The raw-pointer deref gives them an unbounded lifetime, so it compiles.
`destroy()` then frees the box (`Box::from_raw`) right after `mpv_wrapper_destroy`, which is exactly
when mpv emits its shutdown and end-file events. The result is undefined behaviour on player
close. **Fix:** clone the `AppHandle` and `String` before spawning, and confirm the wrapper joins its
event thread before destroy returns.

### D-5: "Start immediately" off creates an item nothing can start
`components/media-details/MediaDetailsModal.tsx:107` sets `status: 'ready'`. No row button,
context-menu entry, bulk action or Rust transition moves `ready` to `queued`. "Resume all" handles
`paused` only. `ready` also counts as busy (`completion.ts:49`, `progress.ts:11`,
`queue_rules.rs:514,554`), so one held item blocks "When everything finishes" forever and pins the
Dock/taskbar progress. **Fix:** a Start action (row, context menu, bulk bar) plus a Rust `queue_start`.

### D-6: Statistics double-count on every launch
`stores/stats.ts:128-185`, `AppProvider.tsx:226,335,462`.
Live `recordCompletion` never advances `backfilledThrough`. So each launch's `backfillFromHistory`
re-counts every download finished since the previous launch, and the totals inflate with every
restart. **Fix:** advance `backfilledThrough` in `recordCompletion`, with a record-then-backfill test.

### D-7: Transfers keyboard shortcuts hijack buttons and confirmation dialogs
`hooks/use-transfer-shortcuts.ts:36-52`. A window-level `keydown` handler `preventDefault`s
Enter, Space and Backspace whenever focus isn't in a text field. Enter and Space no longer activate
the focused sidebar link, Pause All, row actions or a toast's Undo. The "dialog open" guard looks
for `[role="dialog"]`, but ConfirmDialog is a Radix AlertDialog (`role="alertdialog"`). So in the
"Remove and delete files" confirmation, Enter toggles the details panel behind it and Space pauses
the selection. **Fix:** ignore events whose target is a button, link or `[role=button|option|menuitem]`,
and add `alertdialog` and toasts to the guard.

## 3. Medium findings

### Security
| ID | Where | Finding | Fix |
|---|---|---|---|
| S-2 | `torrent.rs:1964-1978`, `1581`, `1785-1792` | A multi-file torrent goes into `<dest>/<name>` with `overwrite: true` even if that folder already exists and belongs to a *different* torrent or to the user ("Season 1"). Pieces that fail the hash check are rewritten, **silently corrupting the earlier download**, and `ledger::record` then authorises the whole pre-existing folder for open, convert and trash. | Reuse the single-file clash logic: fall back to `<name> [hash8]` when the folder exists and isn't claimed by this info hash. |
| S-3 | `lib.rs:907-911`, `1000-1004`, `1873`; `ledger.rs:95`; `rss.rs:112-140` | **Windows:** `is_file`/`exists`/`canonicalize` run on page- or feed-supplied paths *before* the allow-check. A `\\attacker\share\x` path (or `file://host/…`) makes Windows open SMB and send the user's NTLM hash. | Reject UNC, `\\?\` and `\\.\` prefixes, and host-bearing `file:` URLs, before any fs call. |
| S-4 | `hooks/use-clipboard-watcher.ts:48-51` | Clipboard watching is **on by default** and stores *any* clipboard text (passwords, tokens) in `localStorage` before checking whether it is a URL. | Store a hash, or only store after the URL check; consider defaulting it off. |
| S-5 | `ledger.rs:106-137`, `171-187` | On first use the ledger seeds from `$APPDATA/history.json`, which the page can write. A planted `outputFolder: "~/Documents"` with ≥2 files authorises that folder. | Seed from SQLite history, and never seed folders. |
| S-6 | `engine.rs:199-224`, `535-555`, `620-622` | The yt-dlp self-update checks the zip against `SHA2-256SUMS` from the same release (integrity, not authenticity). The signed `.sig` is ignored. The post-install tamper check hashes only the executable, not `_internal/`, where the Python code runs from. | Verify yt-dlp's signature with a pinned key, and record a manifest hash of the unpacked tree. |

### Performance
| ID | Where | Finding | Fix |
|---|---|---|---|
| P-1 | `store.rs:218-227`, `queue.rs:785-791` | Every save is `DELETE FROM queue` plus a re-insert of every item's full JSON: every 2 s while anything runs, and on every status change. With 500 items that is MBs per save plus WAL churn. | Upsert only the ids that changed; delete only removed ids. |
| P-2 | `queue.rs:568`, `661`, `751-764` | `save_now` does that rewrite on the tokio worker that reported completion. A playlist burst means N rewrites back to back. | `spawn_blocking`, or a writer thread. |
| P-3 | `queue.rs:130-160`, `858`, `1019`, `1040` | Synchronous `#[tauri::command]`s run on the **main thread**. | P-4 | `torrent.rs:1060-1073`, `queue.rs:464`, `780` | The full torrent file list is rebuilt every 5 s and carried in every `queue-changed` patch (≈1/s). With 10k files that is hundreds of KB/s over IPC. | Send files and pieces on demand or on change, never inside patches. |

| P-6 | `store.rs:171` | `VACUUM INTO` backup runs on the main thread during setup, and the Library is uncapped, so launch slows as history grows. | Back up in the background after launch. |
| P-7 | `torrent.rs:316-339` | The session lock is held across `start_session().await` (binding, blocklist fetch), so pause, resume and rate changes stall behind it. | `OnceCell`-style init. |
| P-8 | `pages/Queue.tsx:35,118,132,356,360`; `QueueTable.tsx:153` | `QueueRow` is `memo`, but callbacks depend on `items` or are inline, so **every row re-renders on every tick**, each with its own Radix ContextMenu and Tooltips. | P-9 | `AppProvider.tsx:957`; `SubscriptionsProvider.tsx:47,231` | One queue context carries items *and* actions, so the whole shell, Dashboard, Library and Settings re-render per patch. | P-10 | `SubscriptionsProvider.tsx:147-159`, `AppProvider.tsx:680` | Typing in a category or template field changes `addToQueue`, then `runCheck`, then re-arms the scheduler, so **a full yt-dlp check of every subscription runs about 15 s after editing Settings.** | Read `addToQueue` through a ref. |
| P-11 | `pages/Library.tsx:141-149` | `missingFiles` is sent with up to 5,000 paths on every history change. | Debounce, and diff only new rows. |
| P-12 | build output | One 686 KB JS chunk: every page (legal pages and the 1,267-line Settings included) loads at start. | `React.lazy` routes. |

### Architecture
- **A-1: second queue engine.** `AppProvider.tsx:518-658,683-919`, `queue-reducer.ts`, `slots.ts`,
  `retry.ts`, `schedule.ts`, `completion.ts` and `progress.ts` re-implement `queue_rules.rs` for the web
  demo. In desktop mode the page still runs the reducer in `changeItem` and ships whole `settings`
  objects (including `destination`, the D-1 input) back to Rust. **Move the demo engine into
  `MockPrismService` as a JS `RemoteQueue`**, so AppProvider has one code path and rules live only in Rust.
- **A-2: eight `DownloadItem` constructors** (Dashboard ×3, MediaDetailsModal, subscription-check,
  torrent-item, Library requeue, Queue undo) disagree on `retryCount`, placeholder `totalBytes`
  (500 MB / 10 MB / 0; the 500 MB shows as "x / 476.8 MB" and skews the Dock progress) and whether
  `speedLimit` or `referer` apply. One `buildItem(kind, …)` factory.
- **A-3: three error classifiers** (`queue_rules.rs:405-455`, `errors.rs:110-155`, `errors.ts`) with
  different keyword lists. The substring fallbacks misfire (`"full"` ⊂ "fully", `"space"` ⊂ "namespace").
  `PrismError.retryable` is computed and never read. Classify once, in Rust.
- **A-4: oversized components:** Settings.tsx 1,267 lines (≈800 of JSX in one component),
  AppProvider 978, Dashboard 852 (item builders + 4 dialogs + a batch engine), Player 673, DetailPanel 663.

## 4. Low findings

**Security / privacy**
- SSRF: thumbnail, RSS, probe and `.torrent` fetches follow any http(s) URL, including loopback,
  LAN and `169.254.169.254` (`thumbnails.rs:72-104`, `rss.rs:195-201`, `http_engine.rs:939`).
- The page-supplied `-o` can carry yt-dlp `%()` fields expanded after validation (`lib.rs:513-519`).
- `PRISM:PATH=` is accepted from any stdout line (`download_manager.rs:533`, `641-661`). Canonicalise
  and require it inside the template folder.
- Proxy credentials appear in yt-dlp's argv (visible in `ps`), and `redact` doesn't strip
  `user:pass@`. Some stderr is logged unredacted (`lib.rs:333`, `lookup.rs:191`,
  `download_manager.rs:602,630`).
- With a proxy set, DHT, LSD and UDP trackers stay on, so the real IP leaks (`lib.rs:699-702`).
- The lookup cache is also keyed by the site-reported `webpage_url` (`lookup.rs:198-203`).
- `settings.json` (page-writable) drives proxy, watch folders, move-to and the trash keep-list.
  Validated, but inconsistent with the untrusted-page model.
- `player_add_subtitle` has no ledger check (`player.rs:520-538`). `player_state` has a
  read-modify-write race on a shared `.tmp` name.
- `template.rs:116`: `.take(MAX_DEPTH)` drops the *title*, and the cap counts chars, not bytes, so
  multibyte titles fail with ENAMETOOLONG. Windows device names (`CON`, `NUL.txt`) are unhandled in
  `safe_folder_name`.
- `stream_server.rs:190-194`: a 0-byte file gets `Content-Length: 1`, and a non-`bytes=` Range gets a 206.
- Global shortcuts accept an unmodified key (`shortcuts.rs:67-85`).
- `vite.config.ts` `envPrefix: ["VITE_","TAURI_"]` would inline `TAURI_SIGNING_PRIVATE_KEY` if
  `import.meta.env` were ever spread. Drop `TAURI_`.
- CSP `img-src https:` loads remote thumbnails directly when no proxy is set.
- `prism://add?referrer=` isn't shown in the confirm card.

**Correctness**
- A cancelled conversion reports failure (a toast plus a possible `failed` flip).
- Removing a seeding torrent fires "Download complete" and its open/reveal action.
- `archive_due` doesn't re-check that the item is still terminal after its await (a Retry race).
- `downloads.insert` drops a live `Child` without killing it.
- The torrent metadata cache cap is bypassed by two insert paths.
- Concurrency caps disagree: UI 10, engines 16, prefs 50.
- Windows job-handle reuse race (`spawn.rs:103-109`, `212-220`).
- The mpv `wedged` flag never clears.
- A stale `retryAt` survives restart.
- The quit prompt counts paused torrents and ignores conversions.
- Exit doesn't stop lookup processes or shut down the torrent session cleanly.
- The DetailPanel details poll has a stale closure and runs forever.
- Impure `setState` updaters (`Queue.tsx:133`, `Library.tsx:192`).
- `ServiceProvider` has no `.catch`, so an init failure spins forever.
- "Logs exported" toasts even on cancel. `pickDirectory` and `listen()` rejections are unhandled.
- `NumberInput` commits unclamped values.
- `formatBytes` breaks on NaN, negative or ≥1 PB input.
- The ErrorBoundary wraps only the routes and never resets on navigation.

**Dead code:** `hooks/use-mobile.tsx`, the reducer's `startAll`, `IPrismService.pauseDownload`,
`DownloadSettings.retryCount`, `Subscription.categoryId` (no UI), category `kinds` (no UI), and the
whole conversion engine (`convert.rs` + `convertFile`), which no UI ever calls. Stale copy about
a 2,000-row Library cap (`Statistics.tsx:159`, `stats.ts:6`).

## 5. UI/UX review

**Inventory:**
- **Sidebar:** Add (⌘N/⌘L), Dashboard, Transfers, Subscriptions, Library, Statistics; Settings,
  About. Drop-anywhere, tray "Paste & Download", global hotkeys, `prism://` / `magnet:` /
  `.torrent` / watch folders, all behind a confirmation card for external sources.
- **Transfers:** tabs, 7 sorts, category and label filters, search, multi-select, drag or keyboard
  reorder, a rich context menu, and a detail panel (General / Files / Peers / Trackers / Speed).
- **Library:** list or grid, filters, bulk actions with undo, Trash with confirm, missing-file markers.
- **Other:** Subscriptions with include/exclude rules; Statistics; an mpv player window with
  chapters, subtitles, mini mode, resume and streaming.

It is a rich and mostly coherent app. The problems are consistency and reachability.

**Terminology and consistency**
- "Transfers" in the nav vs "queue" everywhere else (View queue, Add to Queue, Active Queue, `/queue`).
- "Canceled" (badges, tabs) vs "cancelled" (`Queue.tsx:400`).
- Title Case buttons ("Pause All", "Add to Queue") beside sentence case ("Download again", "Show in folder").
- The primary verb changes: Fetch (Dashboard), Add (sheet), Subscribe.
- `KindBadge` labels every yt-dlp item "Direct download" (`QueueTable.tsx:462`).
- The Statistics page header reads "Prism" (`AppShell.tsx:134-144`), and every page title appears
  twice (header h1 plus page h2).

**Destructive actions follow no single policy**

| Action | Confirm | Undo |
|---|---|---|
| Cancel a single transfer | – | ✓ |
| Bulk Remove in Transfers | ✓ | – (and it lands active items in the Library as "canceled") |
| Remove one Library row | – | – (though `restoreHistory` exists) |
| Bulk remove in Library | – | ✓ |
| Delete category / label / watch folder | – | – |
| Reset settings | ✓ | – (the dialog doesn't mention it also resets categories, labels, watch folders and shortcuts) |

Proposed policy: **undo for anything that only touches records; confirm only when files on disk are touched.**

**Settings:** about 58 rows in 10 sections. "Speed & schedule" is a 20-row catch-all
(close-to-tray, retries, subscription interval and global shortcuts don't belong there). Clipboard
detection lives under Notifications, and backup/import under Storage. Regroup as Downloads ·
Torrents · Schedule & limits · Behavior (tray, shortcuts, clipboard, notifications) ·
Organization (categories, labels, templates, watch folders) · Network · Updates & data. Add a
search box.

**Adding links:** two surfaces with different parsers. `UrlInput` is line-based, doesn't accept
`.torrent`, and auto-submits arbitrary clipboard text. `AddSheet` is token-based and accepts
`.torrent`. Both show a drop overlay at once. The clipboard watcher only runs while the Dashboard
is mounted, although Settings says "when Prism regains focus". Clip range, "start after" and SHA-256
can only be set on a *queued* item in the detail panel. With free slots an item starts at once, so
these features are effectively unreachable. Move them into the add dialog.

**Discoverability:**
- Empty states never offer an action (`EmptyState` supports one; no caller passes it).
- Transfers says "Paste … on the Dashboard" instead of offering Add ⌘N.
- There is no legend for the Transfers keyboard model and no ⌘F.
- Library rows (`role="option"`) aren't focusable.

**Accessibility:**
- 148 uses of 10–11 px text.
- `muted-foreground` at /60 on the dark background is about 2.2:1, which fails WCAG AA
  (31 uses at /30–/70).
- The detail-panel resize handle isn't focusable.
- Recent Downloads actions are hover-only.
- The MediaDetails filename label isn't associated with its input.
- In its favour: a global `prefers-reduced-motion` rule, `:focus-visible` rings,
  `role=switch` toggles and correct `aria-labelledby` wiring.

**Misleading copy:**
- Turning Notifications off also hides in-app *failure* toasts.
- SetupCard tells macOS users to `brew install ffmpeg`, but ffmpeg is bundled.
- "Extra trackers — newline separated" is a single-line input.
- About shows "v1.0.0" until the version loads.
- The Library nav badge counts every failed row forever.
- Quick Presets aren't persisted, are silently overridden by per-site memory, and are applied
  invisibly in the playlist dialog.

**Missing features users expect:**
- A Start action for held items (D-5).
- Bulk retry of failed items.
- Bulk edit of category, label or destination.
- Rename or change destination after adding.
- Per-item speed limit (only global limits exist, stamped at add time, although Settings says
  they apply "when a download starts").
- Custom format presets.
- Per-subscription quality and category.
- Search by URL, uploader or site.
- Resetting statistics.
- A UI for the conversion engine that already exists.
- Localisation.

## 6. Configuration, CI and dependencies
- **Sound:**
  - Actions pinned to SHAs; a read-only `contents: read` token for CI.
  - The signing key sits in the `release` environment; `cargo audit` and `npm audit` run in CI.
  - fs scope is narrowed to top-level `$APPDATA/*.json`; the asset protocol to `thumbs/`.
  - The player window has no `core:default`; the extension asks only for `contextMenus`.
  - Sentry is opt-in, needs a build-time DSN and is scrubbed on both sides.
- **Gap: Rust tests never run on macOS**, the primary platform (the player, Vulkan driver,
  quarantine and `objc2` code). The `rust-cross-check (macos)` job runs clippy only.
- **Dependencies:** the front-end stack is a major version behind in places (React 18, Vite 5,
  Tailwind 3, next-themes 0.3, lucide 0.462). Nothing insecure today (npm audit gates on high), but
  upgrade in isolated commits before the gap compounds.
- **Entitlements:** `disable-library-validation` + `allow-unsigned-executable-memory` are needed
  for libmpv and MoltenVK. Keep them, but note they widen the dylib-injection surface of an
  unsigned app.
- **No i18n layer:** every string is inline English.

**Where Prism leads.** It is the only one that does video sites, BitTorrent and segmented HTTP in one
queue, with a real player that can **stream a torrent while it downloads**. It is free and open
source, with no ads or telemetry beyond opt-in crash reports. Its security engineering (per-window
ACLs, a tokenised stream server, verified sidecars, an audited CI) is ahead of every
closed-source competitor that can be inspected, and on par with qBittorrent.

**Where it trails.**
1. **Unsupported pages.** Downie's User-Guided Extraction and IDM's capture rescue pages yt-dlp
   can't parse. Prism's fallback is "download as file".
2. **Trust at install.** An ad-hoc-signed macOS app and an unsigned Windows installer meet
   Gatekeeper and SmartScreen warnings that every paid competitor avoids. This is a known cost of
   the free-tooling rule and worth stating on the download page.
3. **Remote control.** qBittorrent, Transmission and JDownloader (MyJD) can be driven from
   another device.
4. **Safari.** Downie's strongest integration on macOS.
5. **Polish at the edges.** Competitors are simpler. 4KVD's Smart Mode and Downie's paste-and-go
   finish a download in one action; Prism's power features (clip, checksum, start-after) are
   hard to reach.

**Deliberately not recommended.** File-hoster premium-account plugins and captcha handling
(JDownloader's niche) are legally murky and a maintenance sink. A torrent search engine
(qBittorrent) moves Prism toward piracy tooling for little benefit.
