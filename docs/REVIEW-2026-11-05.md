# Prism review — 2026-11-05

Third-party style security and feature review of **v2.3.6** (`main` 32b29b8) plus
the unmerged **play-any-file** branch (PR #28, 12007f0). It follows
[REVIEW-2026-11-01.md](REVIEW-2026-11-01.md): that review's Phase A shipped in
2.3.4, and everything after it is re-checked here rather than assumed.

**Method:** read the code that changed since 11-01 (2.3.5 re-encode, 2.3.6
encoder picker, PR #28), re-ran the dependency audits against fresh databases,
re-checked the open work-plan items in the tree, and tested one security claim
against the shipped binary (mpv playlist lockdown, §1.1).

**Summary**

- **Security:** no High or Critical findings. The core design is sound and held up
  where tested: Rust owns every trust decision, the page is untrusted, each window
  gets its own capabilities, and the player is locked down.
- **Open risks:** mostly hygiene items carried over from 11-01. Nothing from Phases
  B–D of that work plan has landed.
- **Biggest practical risk:** release reliability. The Windows and Linux media builds
  are pinned to upstream nightlies that get deleted (R-1).
- **Biggest product issue:** one introduced in 2.3.5/2.3.6. The "make it play on Apple
  devices" re-encode now also runs on Windows and Linux, where it's mostly unwanted and
  can be slow (B-1).
- **Feature gap:** the player is now general-purpose (PR #28) but still lacks what makes
  a desktop player usable day to day: playlists and next file, "Open With Prism", and
  recent files.

## 1. Security

### 1.1 Verified good

| Area | What was checked | Result |
|---|---|---|
| mpv lockdown | Loaded the **shipped** `libmpv.dylib` with Prism's options and played `.mkv` files that were really HLS, M3U and ffconcat playlists pointing at a local HTTP server | No request with `access-references=no`. Control run with `yes`: HLS and M3U **did** fetch. The S-7 fix (09-23) works. |
| Stream server | `stream_server.rs` | Binds 127.0.0.1 on an OS-chosen port. A 32-byte token per launch, compared in constant time. Host header pinned. No CORS. |
| Window capabilities | `capabilities/*.json` + `every_command_is_declared_and_granted_to_the_right_window` | Player-only commands are granted only to the player. Engine/queue commands are granted to no window. PR #28's two new commands are added to the test. |
| Paths from the page | `validate_open_path`, `ledger::require_recorded`, `is_openable_media` | Unchanged and still applied to every page-supplied path. PR #28 bypasses roots/ledger **only** for paths Rust itself got from a dialog or an OS drop event. |
| ffmpeg/ffprobe on downloads | convert.rs, playable.rs, encoders.rs | `-protocol_whitelist file,pipe` on every run that reads a download. 2.3.6 added it to the two ffprobe calls that lacked it. The encoder trial reads only `lavfi`. |
| Quarantine | download_manager.rs | The re-encode replaces the file **before** the quarantine and ledger step, so the replaced file is still flagged. |
| Updates | release run 41892343460 | `latest.json` lists 9 platforms. macOS signature verified against the app's pubkey. yt-dlp engine updates are PGP-checked (`engine.rs`). |
| Webview CSP | tauri.conf.json | `default-src 'self'`, `object-src 'none'`. `connect-src` is limited to Sentry (opt-in). |

## 2. Bugs and UX regressions

| ID | Sev | Finding | Where | Fix |
|---|---|---|---|---|
| B-1 | **Med** | **The Apple-playback re-encode runs on every platform.** Since 2.3.5, any VP9/AV1/Opus MP4 download is re-encoded after it finishes. 2.3.6 made that work on Windows and Linux too, where the reason (QuickTime, iMessage, iOS) mostly doesn't apply. Without a usable GPU it falls back to **software OpenH264**, so a 4K "best" YouTube download can spend longer re-encoding than downloading. It also loses quality against a fixed bitrate, and it shows only "processing" with no percentage. On a Mac it also silently turns an AV1/VP9 download the user chose into H.264. | `download_manager.rs` ~616 (`!audio_only && !keep_original_container`) | (1) Make it its own setting, "Make videos play on Apple devices", on by default on macOS and off elsewhere. (2) Skip it when only a software encoder exists and the video is above 1080p. (3) Report progress: playable.rs could reuse convert.rs's `-progress` parsing. |
| B-2 | Low | **No free-space check before the re-encode,** though it needs room for a second copy of the file. If it fails, the original is kept (by design), but a full disk is reported only in the log. | `playable.rs make_playable` | `fs2::available_space` ≥ input size, else skip with a log line. |
| B-3 | Low | **⌘O "Play a File…" isn't gated on `player_available`,** unlike the Library button. On a build without libmpv it opens a player window that fails to start. | PR #28, `AppShell.tsx playAFile` | Check `player_available` first and toast if it's false. |
| B-4 | Low | **The README has drifted.** The feature list doesn't mention Convert, direct-link downloads, RSS feeds, or (after PR #28) playing any file. "Browser integration — Firefox extension" is stale: a Chromium build is released too. | `README.md:30-52` | Docs pass. |
| B-5 | Low | **ROADMAP is stale.** Phase 3 items that have landed (A-1, A-2, A-3, React 19, Rust tests on macOS) and S-6 (PGP) are still unticked. There's no section for 11-01 or this review. | `ROADMAP.md:42,58-63` | B6 from the 11-01 work plan. |

Still open from 11-01, unchanged:
- B4: the next-themes script warning under React 19.
- P-1: Library "Clear" calls `removeFromHistory` once per row.
- P-2: synchronous `std::fs` calls in async http_engine paths.
- P-3: no free-space check before starting a torrent.
- C1–C4: narrow windows, clearing the URL box, the torrent free-space display, disabled-with-reason actions.

## 3. Features — what we have

**Downloading**
- yt-dlp with honest quality picks, playlists and batch adds, SponsorBlock, embedded metadata and chapters.
- Browser cookies, a proxy, per-site presets.
- Direct HTTP downloads with segments and resume.
- BitTorrent: file selection, peers, ratio and seeding rules, UPnP, streaming while it downloads, import from other torrent clients.
- Watch folders, RSS feeds and channel subscriptions.
- Quiet hours, speed limits, "when done" actions, global shortcuts, tray quick-add.
- Clipboard detection, `prism://` deep links, Firefox/Chromium extensions plus a bookmarklet.

**Library and files**
- A virtualized Library with search, categories and labels, grid/list views.
- A missing-file check, backup/import/dedupe, a content index.
- Convert (MP4 H.264/HEVC/remux, MP3/M4A/Opus).
- The post-download Apple-playback fix.

**Player** (mpv, macOS and Windows)
- HDR, every codec, audio and subtitle tracks, sibling subtitles, chapters.
- Speed, a mini player, resume position, torrent streaming.
- **New in PR #28:** play any local file (⌘O, Library button, the player's own Open), drag-and-drop onto the player, subtitles from any folder.

**Platform**
- Signed auto-updates on all three OSes, a Homebrew cask, an LGPL-only media stack.
- Opt-in crash reports; no telemetry.

## 4. Features — what's needed

### 4.1 Player, round 2 (finishes what PR #28 started)

| ID | Feature | Notes |
|---|---|---|
| P-A | **Folder and playlist playback, plus next/previous file** | Pick several files, or play a folder. Queue them with mpv's `append`, never handing mpv the directory (work plan A2 option 2). Next/Prev buttons plus `N`/`P` keys. Auto-advance to the next episode in the same folder. |
| P-B | **"Open With Prism" for video and audio files** | `bundle.fileAssociations` only lists `.torrent` today. Add media types with role `Viewer`, **not** the default handler. | P-C | **Recent files** | A short list (10) in the player and in Library's "Play a File…" menu. Store paths in Rust only. It's the privacy-sensitive counterpart to S-6, so make it clearable. |
| P-D | **Everyday controls** | Audio delay (sync); frame step (`,`/`.`); screenshot to `~/Pictures`; A-B loop; aspect/zoom; a keyboard shortcut sheet (`?`). All are mpv properties or commands, each added to `validate_player_property` rather than as a general passthrough. |
| P-E | **Linux player** | The README promises the player on macOS and Windows only. libmpv is in the AppImage's reach. Measure the effort before promising it. |
| P-F | Subtitle search (OpenSubtitles) | Optional. Free API tier with a user-supplied key. Lower priority. |

### 4.2 Downloader and product (carried, re-ranked)

1. **F-2 / P-3 free-space forecast and torrent preflight:** it prevents real failures and is cheap.
2. **F-3 Re-download / Locate… for Missing Library entries:** Locate goes through a Rust picker that records the new path in the ledger, the same pattern as PR #28.
3. **F-1 Sequential "watch while downloading" per torrent:** pairs naturally with P-A.
4. **F-6 Copy magnet / source link** (small), **F-4 subscription regex + dry run**, **F-5 speed history chart**.
5. Phase 4 UX: one add pipeline, custom presets, per-item speed limit, a Settings search.
6. Phase 5 competitive gaps: page capture for unsupported sites, a Safari extension, an optional LAN web UI (token-guarded, off by default), torrent creation, Smart mode.
7. winget manifest (open since July).
