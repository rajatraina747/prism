  - CI runs a newer stable clippy than the local rustc, so new lints may only show up
    in CI.

  - There's no `timeout` command on this Mac.
  - Commit or stash before any `git reset --hard`.
  - No Co-Authored-By trailers in this repo.
- **Release:** bump the version in package.json, package-lock, tauri.conf.json,
  Cargo.toml and Cargo.lock. Tag, then Rajat approves the `release` environment.
  After that, verify the draft, publish, and bump the cask (`prism-downloader`).

## Phase A: 2.3.3 hotfix (torrent paths and actions)

### A1. Record and quarantine torrents when they finish downloading, not when seeding ends (B-1, S-1) **High**

- [ ] Status:
- **Where:**
  - `src-tauri/src/torrent.rs`: the poll loop in `start_torrent`. `finished_at` is
    set at ~line 1085. `quarantine_torrent` and `record_finished` currently run only
    at ~1150/1181 (after seeding) and ~1370 (user stops seeding).
- **Do:**
  1. On the first tick where `stats.finished` is true, run `quarantine_torrent` and
     `record_finished` in `spawn_blocking`. Work out `single_file` the same way as at
     the end of the loop.
  2. For a multi-file torrent, also record `own_dir` right after the add. Prism owns
     that folder, and doing this lets completed files be played while the rest still
     download.
  3. Keep the end-of-seeding call, since a move changes the path. The ledger dedupes,
     so a second record is harmless. A move must record the **new** path, as it does now.
  4. On restart, a restored torrent that is already finished also hits the
     first-finished edge, so earlier seeding torrents heal themselves.
- **Test:** a seeding torrent's path passes `ledger::require_recorded` and carries
  the quarantine xattr on macOS. Use the existing offline-session test harness
  (`offline_session`).
- **Done when:** a torrent at 100% and seeding can be played or opened from both the
  Library and the Queue detail panel, and `xattr -l` shows `com.apple.quarantine` on
  its files.
